ภาคผนวก

ของที่ต้องเปิดบ่อยที่สุด รวมไว้ที่เดียว — ภาคผนวกไม่ได้มีไว้อ่านตามลำดับ มันคือของที่ควรอยู่ในแท็บที่เปิดค้างไว้ตอนทำงาน

เช็คลิสต์รวม ~190 ข้อ gate 47 ตัว บันทึกการแก้ไข 28 จุด พิมพ์ได้

Aตารางเลือกเทคนิคใน 2 นาที ⭐

อ่าน requirement แล้วมองหาลักษณะพวกนี้ — นี่คือ 80% ของงาน test analysis

ถ้า requirement มีลักษณะนี้ใช้เทคนิคอยู่ที่
มีค่าที่เรียงลำดับได้ + มีขอบBVA (+ EP เสมอ)L1.2
มีค่าเป็นกลุ่มที่ไม่เรียงลำดับEquivalence PartitioningL1.1
มี “และ / หรือ / ถ้า…ยกเว้น” ≥ 2 เงื่อนไขDecision TableL1.3
มี “สถานะ / หลังจาก / ก่อนที่ / ต้อง…ก่อน”State TransitionL1.4
มี “รองรับ A, B, C บน X, Y” (config)PairwiseL1.5
มีหลายมิติที่ไม่รู้ว่าครบยังClassification TreeL1.6
เป็น flow ที่มีลำดับขั้นและมีทางแยกUse Case / ScenarioL1.6b
เป็นสูตรคำนวณที่ตรวจผลยากMetamorphic relationL1.11
เป็นโค้ดที่มี boolean ซับซ้อน + แตะเงินMC-DCL1.7
ไม่มี spec / spec ห่วย / ของใหม่Exploratory + Fault attackL1.9
ไม่รู้จะเริ่มตรงไหนRisk register ก่อนเสมอL1.10
มี invariant ที่ประกาศได้ชัดProperty-basedL5.2
state machine ≥ 5 statesModel-basedL5.3
refactor โค้ดที่ไม่มีเทสGolden master หรือ differential fuzzL5.12
เขียน implementation ใหม่แทนของเก่าShadow runL5.15
ไม่รู้ว่าเทสที่มีอยู่ดีพอมั้ยMutation testingL5.1
เกณฑ์ความลึกจาก risk score
Score 16-25 : หลายเทคนิคซ้อน + exploratory + NFR + property/mutation Score 9-15 : เทคนิคหลัก 1-2 ตัว ทุก commit Score 4-8 : smoke ใน CI + regression รายสัปดาห์ Score 1-3 : เทสตอน release หรือไม่เทส (⭐ ต้องบันทึกว่าไม่เทส)

Lข้อโต้แย้งที่จะเจอ (และคำตอบ)

รวมข้อโต้แย้งที่จะโดนจากคนอื่น — และจากตัวคุณเองตอน 5 ทุ่มก่อน deadline ซึ่งเป็นเวอร์ชันที่อันตรายกว่า

ข้อโต้แย้งคำตอบสั้นอ้างอิง
“gate เยอะขนาดนี้ pipeline จะช้ามาก” gate ส่วนใหญ่รัน < 30 วินาที และเรียงตาม signal-per-second · tiered DoD ทำให้ T0 รันแค่ 3 gate L2.11 · L4.7
“เขียนเทสเยอะขนาดนี้ ไม่มีเวลาทำฟีเจอร์” 78 เทสต่อฟีเจอร์ แต่ 41 ตัวเป็น unit ที่ it.each เขียน 15 นาที · E2E เหลือ 8 ตัว L1.14
“agent เขียนเทสให้ได้อยู่แล้ว ไม่ต้อง red-proof” agent เขียนเทสจากโค้ดที่เห็น → oracle มาจากโค้ดเอง → ยืนยันว่าโค้ดทำสิ่งที่โค้ดทำ L2.14 · L4.12
“ผม review เองที่ S8.5 อยู่แล้ว” คำถามคือ ยังจับได้อยู่มั้ย — วัดด้วย approval drill · blind_approve_rate ตีความคนเดียวไม่ได้ L4.5
“เขียนใน CLAUDE.md ว่าห้ามแล้ว” prompt = คำขอ · structural constraint = กำแพง · เกณฑ์: ถ้าละเมิดแล้วกู้ไม่ได้ ต้อง structural L4.12
“coverage 85% แล้ว น่าจะพอ” coverage บอกว่าโค้ดถูกรัน ไม่ได้บอกว่ามันถูก · ดู mutation score กับ oracle provenance แทน L5.1
“build เขียวตลอด แสดงว่าดี” ถ้ามี retry 2 ครั้ง p=5% จะเขียว 97.5% โดยไม่แก้อะไรเลย · วัด flake ที่ attempt แรก L2.7
“gate นี้ไม่เคยจับอะไรได้เลย ลบทิ้งเถอะ” ถามก่อน: “ถ้าลบ จะมีใครทำสิ่งที่มันห้ามมั้ย” — ถ้ามี = มันกำลังทำงานอยู่ (deterrence) L2.13
“load test ผ่าน p95 = 400ms สบายมาก” ยิง record เดิมซ้ำมั้ย · ตัด warm-up ถูกมั้ย · closed model มั้ย · ledger ยังตรงมั้ย L3.2.8
“ยังไม่มีผู้ใช้เยอะ ยังไม่ต้องทำ security” actor ที่อันตรายที่สุดคือ ผู้ใช้ที่ลงทะเบียนแล้ว ไม่ใช่ hacker — เขามีตั้งแต่วันแรก L3.4A
“เทสภาษาไทยไม่สำคัญเท่า logic” collation ที่ไม่ตรงกับ DB ทำให้ pagination มีรายการหาย · พ.ศ. ผิดทำให้ปล่อยเด็กเข้าระบบ L3.7
“LINE in-app เทสด้วย UA spoof ก็พอ” UA spoof ไม่จับ third-party cookie ที่ถูกบล็อก — ซึ่งคือปัญหาหลัก · ต้องทำด้วยมือ L3.6
“prompt injection เป็นเรื่องทฤษฎี” Playwright อ่านหน้าเว็บที่ผู้ใช้กรอกข้อความเอง → เนื้อหานั้นเข้า context ของ agent จริง L5.11
“ทำคนเดียว ไม่ต้องมีเอกสาร” เอกสารไม่ได้มีไว้สื่อสารกับคนอื่น มันมีไว้สื่อสารกับตัวคุณตอนเหนื่อย · และ bus factor = 1 คือ risk 25/25 L4.1 · L4.6
“ครั้งนี้ deadline จริงๆ ขอข้าม gate หน่อย” ใช้ emergency path ที่เขียนไว้ล่วงหน้า — มี gate ที่ข้ามได้และข้ามไม่ได้ระบุไว้แล้ว · การยอมนอกกรอบครั้งเดียว = จุดจบของ gate นั้น L4.8
