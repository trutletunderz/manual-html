# Emergency Path

> **⭐ นี่คือข้อยกเว้นเดียวของ "ไม่มี gate ที่ข้ามได้"**
> และมันปลอดภัยได้ก็ต่อเมื่อ **เขียนไว้ล่วงหน้าตอนที่ยังไม่มีอะไรพัง**
> ถ้าไปคิดตอนไฟไหม้ คุณจะข้าม gate ที่ไม่ควรข้าม

---

## ลำดับการหยุดเลือด — ทำจากบนลงล่าง หยุดเมื่อเลือดหยุด

| # | วิธี | เวลา | เพิ่มความเสี่ยงใหม่? |
|---|---|---|---|
| 1 | **Feature flag off** | ~10 วินาที | ไม่ |
| 2 | **Rate limit ที่ edge** | ~1 นาที | ไม่ |
| 3 | **Traffic shift ไป revision เก่า** | ~1 นาที | ไม่ |
| 4 | **Hotfix ข้าม gate** | ~15 นาที | 🔴 **ใช่** |

**⭐ ห้ามเริ่มที่ข้อ 4**
90% ของเหตุการณ์จบที่ข้อ 1–3
และข้อ 4 คือทางเดียวที่เพิ่มความเสี่ยงใหม่ตอนที่ระบบไม่มั่นคงอยู่แล้ว

---

## Hotfix: gate ที่ข้ามได้ / ข้ามไม่ได้

### ข้ามได้
- E2E ทั้งหมด
- visual regression
- a11y
- load test
- LLM reviewer (S7)
- mutation testing

### ⭐ ข้ามไม่ได้ — ไม่มีข้อยกเว้น
- `tsc --noEmit`
- unit test ที่เกี่ยวข้องกับไฟล์ที่แก้
- red-proof (ถ้าเพิ่มเทสใหม่)
- authz enforcement
- race condition
- invariant check

**เหตุผล:** gate ที่ข้ามไม่ได้คือกลุ่มที่ **ป้องกันไม่ให้ hotfix สร้างปัญหาใหม่**
การข้ามมันตอนฉุกเฉิน = เพิ่มความเสี่ยงตอนที่รับความเสี่ยงไม่ไหวแล้ว

## คำสั่ง

```bash
EMERGENCY_REASON="<อธิบายสั้นๆ ว่าเกิดอะไร>" \
INCIDENT_ID="<ticket id>" \
  ./scripts/emergency-deploy.sh
```

สคริปต์จะ:
1. บังคับให้ยืนยันว่าลองข้อ 1–3 แล้ว
2. รัน gate ที่ข้ามไม่ได้
3. บันทึกลง `docs/emergency-log.md`
4. deploy

---

## หลังจบเหตุการณ์ — บังคับ ไม่ใช่ทางเลือก

- [ ] ภายใน **24 ชม.** — เขียน postmortem (`docs/templates/postmortem.md`)
- [ ] ภายใน **48 ชม.** — เพิ่มเทสที่จับเหตุการณ์นี้ได้ (ต้องแดงก่อนแก้)
- [ ] ภายใน **1 สัปดาห์** — รัน gate ที่ข้ามไปทั้งหมดย้อนหลัง
- [ ] อัปเดต `pipeline-skill/fault-attacks.yaml`
- [ ] ทบทวน error budget policy ถ้าใช้ budget ไปเยอะ
