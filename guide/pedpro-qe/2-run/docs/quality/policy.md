# Quality Policy

> **สถานะ:** ร่าง — ค่าทั้งหมดเป็นค่าตั้งต้นที่ต้องแทนด้วยตัวเลขจริง
> **แก้ไขล่าสุด:** `<YYYY-MM-DD>` · **ทบทวนครั้งถัดไป:** `<+12 เดือน>`
> **ผู้ตัดสิน:** `<ชื่อ>`

เอกสารนี้ไม่ได้มีไว้สื่อสารกับคนอื่น
**มันมีไว้สื่อสารกับตัวคุณเองในวันที่เหนื่อยและใกล้ deadline**
วันนั้นคุณจะอยากข้าม gate และคุณจะมีเหตุผลดีๆ เตรียมไว้แล้ว

## 1. สิ่งที่เราไม่ยอมให้เกิดเด็ดขาด (ไม่มี error budget)

| # | ข้อ | วัดด้วย | สถานะ |
|---|---|---|---|
| 1 | เงินของผู้ใช้ผิดพลาด แม้ 1 สตางค์ | INV-1 (ทุก 10 นาที) | ⬜ ยังไม่ได้ติดตั้ง |
| 2 | ผู้ใช้เห็น/แก้ข้อมูลของผู้ใช้คนอื่น | authz gate + audit anomaly | ⬜ |
| 3 | ข้อมูลส่วนบุคคลรั่วออกนอกระบบ (PDPA) | PII scanner | ⬜ |
| 4 | ผู้ที่อายุไม่ถึงเกณฑ์เข้าใช้ระบบได้ | INV-5 | ⬜ |

**ทั้ง 4 ข้อวัดด้วย invariant ที่ทำงานใน production ตลอดเวลา
ไม่ใช่ด้วยเทสที่รันเฉพาะตอน CI**

---

## 2. ค่าเริ่มต้นของระบบ

- **fail-closed** — ถ้าตรวจไม่ได้ = ไม่ผ่าน
- **deterministic ก่อน judgment** — gate ที่ตัดสินผิดไม่ได้ ต้องรันก่อนเสมอ
- **ไม่มี gate ที่ข้ามได้** ยกเว้น emergency path ที่นิยามไว้ล่วงหน้า
- **structural ก่อน prompt** — ข้อจำกัดที่ละเมิดแล้วกู้ไม่ได้ ต้องบังคับด้วยโครงสร้าง

---

## 3. ลำดับความสำคัญเมื่อขัดแย้งกัน

```
ความถูกต้องของเงิน  >  ความปลอดภัย  >  ความพร้อมใช้งาน
>  ความเร็ว  >  ความสวยงาม
```

**ตัวอย่างการใช้:** ถ้าต้องเลือกระหว่าง "ระบบช้าลง 300ms"
กับ "มีโอกาส 0.1% ที่ยอดเงินจะเพี้ยน" → เลือกช้าลง ไม่ต้องคิด

## 4. Metric ที่ใช้ตัดสินใจ

> ค่าทั้งหมดยังเป็น `—` เพราะยังไม่ได้วัด
> รัน `./scripts/phase1-audit.sh` และ `./scripts/gate-drill.sh` เพื่อเติมช่องแรก

| Metric | เป้า | ค่าปัจจุบัน | วัดเมื่อ |
|---|---|---|---|
| `escaped_defect_rate` | ลดลง qoq | — | — |
| `approval_drill_pass_rate` | > 80% | — | — |
| `blind_approve_rate` | ตีความคู่กับข้างบน | — | — |
| `repeat_incident_rate` | < 10% | — | — |
| `change_failure_rate` | < 15% | — | — |
| `mttr` | < 60 นาที | — | — |
| `gate_drill_pass` | 100% | — | — |
| `first_pass_rate` | > 70% | — | — |
| `consolidation_ratio` | > 50% | — | — |

**⭐ `blind_approve_rate` ตีความคนเดียวไม่ได้**
มันสูงได้ทั้งเพราะระบบดี และเพราะคนหมดความสนใจ
ต้องดูคู่กับ `approval_drill_pass_rate` เสมอ

## 5. เรื่อง agent

- agent รับผิดชอบไม่ได้ → **accountability อยู่ที่คนเสมอ**
- ข้อจำกัดที่สำคัญต้องเป็น structural ไม่ใช่ prompt
- ทุกอย่างที่ agent ผลิต ถือว่า**ยังไม่ถูกตรวจสอบ**จนกว่าจะผ่าน gate ที่คนออกแบบ
- S7 (LLM reviewer) นับเป็น **filter ที่ลดภาระ** ไม่ใช่ code review เชิงกระบวนการ

## 6. สิ่งที่เราจงใจไม่ทำ (พร้อมเงื่อนไขเปลี่ยนใจ)

## 7. Tiered Definition of Done

| Tier | Risk | ตัวอย่าง | Gate set | S8.5 |
|---|---|---|---|---|
| T0 | 1–3 | typo · สี · comment | static + unit + build | ⬜ auto-approve (ยังไม่เปิด) |
| T1 | 4–8 | layout · ฟิลด์ที่ไม่กระทบ logic | + integration + a11y + i18n | required |
| T2 | 9–15 | business logic · endpoint ใหม่ | + contract + authz + E2E | required |
| T3 | 16–25 | เงิน · auth · webhook · migration | + race + load + canary | required + exploratory |

**เงื่อนไขก่อนเปิด auto-approve T0** (ต้องครบ 4 ข้อ):

1. ⬜ นิยาม T0 แคบตามโค้ด `classifyTier()` ซึ่ง fail-closed
2. ⬜ audit sampling 10% ทำงานจริง
3. ⬜ มีข้อตกลงว่า incident ครั้งเดียวจาก T0 → ยกเลิกทันที
4. ⬜ วัด `escaped_defect_rate` ของ T0 แยกได้
